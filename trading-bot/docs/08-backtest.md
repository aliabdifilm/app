# ۸) بک‌تست و اعتبارسنجی Walk-Forward

## ۸.۱ قبل از هر چیز: داده تاریخی

کیفیت بک‌تست از کیفیت داده می‌آید.

۱. در متاتریدر: **Tools ← Options ← Charts** و `Max bars in chart` را روی
   `Unlimited` بگذارید.
۲. **View ← Symbols** ← نماد مورد نظر ← تب **Bars** یا **Ticks** ← دکمه
   **Request** را بزنید و اجازه دهید کامل دانلود شود.
۳. برای بک‌تست دقیق، حالت **Every tick based on real ticks** بهترین است، ولی
   داده تیک واقعی حجیم و کند است. برای شروع، **1 minute OHLC** کافی است.

## ۸.۲ بک‌تست ساده

1. کلید **Ctrl+R** برای باز کردن Strategy Tester.
2. تنظیمات:

| فیلد | مقدار |
|---|---|
| Expert | `ApexAlgo\ApexAlgoEA` |
| Symbol | `EURUSD` |
| Period | `M15` |
| Model | `1 minute OHLC` |
| Date | حداقل ۲ سال |
| Deposit | `10000` |
| Leverage | مطابق حساب واقعی شما |
| Optimization | `Disabled` |

3. در تب **Inputs** این‌ها را تنظیم کنید:

```
InpRemoteEnabled  = false     ← WebRequest در تستر کار نمی‌کند
InpUseNewsFilter  = false     ← تقویم اقتصادی در تستر در دسترس نیست
InpLogToFile      = false     ← سرعت را بالا می‌برد
InpShowPanel      = false
```

4. **Start** را بزنید.

## ۸.۳ خواندن نتیجه — به چه چیزی نگاه کنیم

**به نمودار سرمایه و سود کل نگاه نکنید.** این‌ها فریبنده‌ترین اعداد هستند.

| معیار | حد قابل قبول | چرا مهم است |
|---|---|---|
| **Profit Factor** | ۱.۳ تا ۲.۵ | زیر ۱.۳ حاشیه کافی ندارد. بالای ۳ تقریباً همیشه بیش‌برازش است. |
| **تعداد معاملات** | حداقل ۲۰۰ | زیر آن، نتیجه شانس است نه آمار. |
| **حداکثر افت** | زیر ۲۰٪ | آیا می‌توانید این را در واقعیت تحمل کنید؟ |
| **Recovery Factor** | بالای ۲ | سود کل نسبت به بزرگ‌ترین افت. |
| **Expected Payoff** | مثبت | میانگین هر معامله. |
| **طولانی‌ترین رشته ضرر** | زیر ۸ | آیا بعد از ۸ ضرر پشت‌سرهم ربات را خاموش می‌کنید؟ |

### نشانه‌های خطر

- **کمتر از ۱۰۰ معامله** → آماری بی‌معنا.
- **نمودار سرمایه کاملاً صاف و رو به بالا** → تقریباً همیشه یعنی باگ یا
  look-ahead bias.
- **تمام سود از ۲ یا ۳ معامله** → شانس بوده، نه مزیت.
- **Profit Factor بالای ۵** → خطای منطق یا بیش‌برازش شدید.

## ۸.۴ Walk-Forward — تست واقعی

بک‌تست ساده فقط می‌گوید «آیا منطق کار می‌کند». Walk-Forward می‌گوید
«آیا این مزیت واقعی است یا بیش‌برازش».

### مرحله ۱ — ساخت برنامه

```bash
cd trading-bot/tools
python walkforward.py plan \
    --start 2023-01-01 --end 2026-06-30 \
    --is-months 6 --oos-months 2 \
    --symbol EURUSD --period M15 \
    --deposit 10000
```

خروجی: جدول پنجره‌ها و فایل‌های `.ini` در `walkforward/ini/`.

هر پنجره دو فایل دارد:
- `wNN_is.ini` → بهینه‌سازی روی بازه درون‌نمونه
- `wNN_oos.ini` → تست روی بازه خارج‌نمونه

### مرحله ۲ — اجرای بهینه‌سازی‌ها

**متاتریدر باید کاملاً بسته باشد.**

```bash
python walkforward.py run --stage is \
    --terminal "C:\Program Files\MetaTrader 5\terminal64.exe"
```

ترمینال برای هر پنجره باز و بسته می‌شود. این کار ساعت‌ها طول می‌کشد.

### مرحله ۳ — انتقال پارامترهای برنده (دستی)

متاتریدر امکان خروجی گرفتن خودکار از برندگان بهینه‌سازی را ندارد. برای هر پنجره:

۱. متاتریدر را باز کنید، تب **Optimization Results**.
۲. روی ستون **Complex Criterion** مرتب کنید.
۳. **به دنبال فلات بگردید، نه قله.** اگر بهترین نتیجه `ADX=23` است ولی
   `ADX=22` و `ADX=24` بد هستند، آن نویز است. ردیفی را انتخاب کنید که
   همسایه‌هایش هم نتایج خوبی دارند.
۴. آن مقادیر را در فایل `wNN_oos.ini` جایگزین کنید.

مثال، در بخش `[TesterInputs]` فایل `w01_oos.ini`:

```ini
InpMinScore=0.45
InpAtrStopTrend=2.0
InpRRTrend=2.0
InpAdxTrendMin=24.0
InpDonchianPeriod=20
InpTrailAtrMult=2.0
```

### مرحله ۴ — اجرای تست‌های خارج‌نمونه

```bash
python walkforward.py run --stage oos \
    --terminal "C:\Program Files\MetaTrader 5\terminal64.exe"
```

### تفسیر حکم

| حکم | معنی | کار بعدی |
|---|---|---|
| `PASS` | بخش معناداری از عملکرد حفظ شده | برو به دمو |
| `MARGINAL` | مرزی | با پنجره‌های متفاوت دوباره تست کن |
| `INCONCLUSIVE` | معامله کافی نیست | بازه طولانی‌تر یا تایم‌فریم پایین‌تر |
| `REJECT` | بیش‌برازش یا ضررده | پارامترها را عوض نکن — منطق را بازبینی کن |
| `SUSPICIOUS` | خارج‌نمونه از درون‌نمونه بهتر است | دنبال باگ look-ahead بگرد |

> ⚠️ اگر حکم `REJECT` گرفتید، **وسوسه نشوید پارامترها را تغییر دهید تا PASS
> شود**. این دقیقاً همان بیش‌برازشی است که می‌خواستید از آن فرار کنید.

## ۸.۵ قوانین بهینه‌سازی

۱. **پارامترهای ریسک را هرگز بهینه نکنید.** `InpRiskPercent`،
   `InpMaxDrawdownPct` و `InpDailyLossLimitPct` تصمیم‌های سیاستی درباره بقا
   هستند، نه متغیرهایی برای حداکثرسازی. ابزار walkforward آن‌ها را ثابت نگه
   می‌دارد.
۲. **همزمان بیش از ۶ پارامتر بهینه نکنید.**
۳. **معیار `Complex Criterion` (شماره ۶) را استفاده کنید**، نه سود خالص.
   سود خالص، شما را به سمت پارامترهای پرریسک هل می‌دهد.
۴. **یک نماد در هر زمان.**

## ۸.۶ فوروارد تست روی دمو

پس از گرفتن `PASS`، **حداقل ۴ هفته** روی دمو اجرا کنید. این مرحله قابل حذف نیست.

بک‌تست این‌ها را شبیه‌سازی نمی‌کند:

- اسپرد متغیر در ساعات مختلف
- لغزش و ریکوت واقعی
- سوآپ شبانه دقیق
- گپ آخر هفته
- قطعی اینترنت و کندی سرور

### مقایسه دمو با بک‌تست

پس از ۴ هفته دمو:

```bash
cd trading-bot/server
python mt5_bridge.py stats --days 30 --magic 20260921
```

اعداد را با بک‌تست همان بازه مقایسه کنید. تفاوت ۲۰ تا ۳۰ درصدی طبیعی است.
تفاوت بیش از ۵۰ درصد یعنی یک فرض شما در بک‌تست اشتباه بوده — معمولاً اسپرد
یا لغزش.

## ۸.۷ بازآزمون دوره‌ای

بازارها تغییر می‌کنند. هر ۳ تا ۶ ماه:

۱. Walk-Forward را روی داده‌های جدید دوباره اجرا کنید.
۲. اگر `mean_efficiency` به‌طور مداوم افت کرد، استراتژی در حال از دست دادن
   مزیت است.
۳. در آن صورت `InpRiskPercent` را کم کنید و علت را بررسی کنید — نه اینکه
   پارامترها را دوباره بهینه کنید تا خوب به نظر برسند.
