## ۲.۲ اصل طراحی: سرور یک وسیله راحتی است، نه یک وابستگی

این مهم‌ترین تصمیم معماری پروژه است.

اگر سرور کنترل خاموش شود، شبکه قطع شود یا VPS ری‌استارت شود:

- EA **به کار خود ادامه می‌دهد** (رفتار پیش‌فرض، قابل تغییر).
- تمام محدودیت‌های ریسک همچنان اجرا می‌شوند.
- هر پوزیشن باز، حد ضرر خود را **روی سرور بروکر** دارد. حتی اگر کل کامپیوتر
  خاموش شود، بروکر همچنان حد ضرر را اجرا می‌کند.

با ورودی `InpOfflinePolicy` می‌توانید این رفتار را تغییر دهید:

| مقدار | رفتار هنگام قطع ارتباط |
|---|---|
| `KEEP_TRADING` | ادامه کار عادی (پیش‌فرض) |
| `NO_NEW_TRADES` | معاملات باز مدیریت می‌شوند، ورود جدید متوقف |
| `FLATTEN` | همه چیز بسته و ربات متوقف می‌شود |

## ۲.۵ چرا مدیریت معامله در هر تیک، اما ورود فقط در کندل جدید؟

| عملیات | تناوب | دلیل |
|---|---|---|
| ورود جدید | هر کندل بسته | جلوگیری از repainting و معاملات بیش از حد |
| تریلینگ و سربه‌سر | هر تیک | باید به قیمت واکنش نشان دهد، نه به بسته شدن کندل |
| ضربان سرور کنترل | هر N ثانیه (تایمر) | WebRequest کند است و نباید در OnTick باشد |
| بازخوانی ریسک | هر تیک و هر تایمر | تشخیص فوری عبور از سقف افت |

## ۲.۶ نکته مهم درباره WebRequest

`WebRequest` در MQL5 **همگام (synchronous)** است: تا پاسخ نیاید، اجرای برنامه
متوقف می‌ماند. به همین دلیل:

- فقط در `OnTimer` صدا زده می‌شود، هرگز در `OnTick`.
- `InpRemoteTimeoutMs` به‌صورت پیش‌فرض روی ۳ ثانیه است.
- حتی اگر EA برای چند ثانیه مسدود شود، **حد ضرر هر پوزیشن روی سرور بروکر است**
  و مستقل از EA اجرا می‌شود. این یعنی ریسک واقعی پوشش داده شده است.

همچنین `WebRequest` در **Strategy Tester کار نمی‌کند**. برای همین در بک‌تست
باید `InpRemoteEnabled=false` باشد (ابزار walkforward این را خودکار انجام می‌دهد).

## ۲.۷ پروتکل ارتباطی

### درخواست EA به سرور

`POST /api/heartbeat` با هدر `X-Apex-Token`:

```json
{
  "bot_id": "apex-1", "version": "1.0.0", "ts": 1758500000,
  "login": 5012345, "server": "Broker-Demo", "currency": "USD",
  "balance": 10000.0, "equity": 10250.0, "margin_level": 4100.0,
  "day_pnl": 250.0, "day_pnl_pct": 2.5,
  "peak_equity": 10300.0, "drawdown_pct": 0.48,
  "open_positions": 1, "trades_today": 2, "loss_streak": 0,
  "paused": false, "halt": "NONE", "halt_reason": "",
  "risk_percent": 0.5,
  "positions": [ { "ticket": 123456, "symbol": "EURUSD", "side": "BUY", "...": "" } ],
  "symbols":   [ { "symbol": "EURUSD", "spread": 8.0, "note": "regime TREND" } ],
  "ack": [7, 8]

```

### پاسخ سرور

```json
{
  "ok": true, "server_time": 1758500001, "paused": false,
  "commands": [
    { "id": 9, "type": "close_symbol", "symbol": "EURUSD", "value": 0.0 }
  ]
}
```

### چرخه عمر یک دستور

```
ایجاد در پنل  →  تحویل در ضربان بعدی  →  اجرا در EA  →  ack در ضربان بعدی
                          │
                          └─ اگر تا ۳۰ ثانیه ack نیامد، دوباره ارسال می‌شود
```

تمام دستورات **idempotent** هستند: «بستن همه» دو بار اجرا شود، بار دوم کاری
برای انجام دادن ندارد. پس ارسال مجدد بی‌خطر است، در حالی که گم شدن یک دستور
«بستن همه» خطرناک است.

## ۲.۸ مدل امنیتی

| مسیر | محافظت |
|---|---|
| EA ← → سرور | توکن مشترک در هدر، مقایسه constant-time |
| مرورگر ← → سرور | رمز عبور + کوکی نشست امضاشده، محدودیت تلاش ورود |
| تلگرام | فقط `chat_id` های مجاز؛ دستورات خطرناک نیاز به دکمه تأیید |
| هدرهای HTTP | CSP، X-Frame-Options، nosniff، Referrer-Policy |
| سقف ریسک | هم در سرور و هم در EA اعمال می‌شود (دفاع لایه‌ای) |

> **هشدار:** این سرور باید پشت HTTPS باشد. جزئیات در `04-install-vps.md`.
> توکن روی HTTP ساده، قابل شنود است.
